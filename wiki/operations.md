# Operations — laptop to gravelines

Tooling is `just` + `uv`. `just` with no recipe lists them.

| | |
|---|---|
| `just update` | `uv sync --upgrade --group dev` — the only thing that moves `uv.lock` |
| `just lint` / `just fmt` | ruff check + format (line length 100, py313) |
| `just typecheck` | `ty check --error-on-warning` |
| `just test` | `uv run pytest` — needs the network: the live KRCG corpus |
| `just serve` | runs the bot locally from `.env` |
| `just release` | on `main`, clean tree: lint, typecheck, test, bump minor, commit `Release X.Y`, tag, push, then `just github-release` |
| `just github-release` | builds and publishes the GitHub release with its wheel attached — which fires the deploy |
| `just deploy [tag]` | converges a release's wheel onto the host from the laptop — [Deploy](#deploy) |
| `just clean` | drop build artifacts and caches |

The pre-commit ruff hooks are `repo: local` running `uv run ruff`: `uv.lock` is the only ruff pin. A
pre-commit hook also refuses `ansible/vault.yml` without the vault header.

Python ≥ 3.13, `uv_build` backend, src layout. Runtime dependencies: `aiohttp`, `hikari`, `krcg`,
`unidecode`.

## Environment

- `DISCORD_TOKEN` — the bot token. `.env` (git-ignored) carries the shared development token,
  age-encrypted in the repo: `age -d -i ~/.ssh/<key> -o .env ansible/secrets/dev-env.age`. Run the dev
  bot against a test guild, never with the production token.
- `PYTHONOPTIMIZE` — set (production sets `1`), `__debug__` is false and logging is INFO; unset,
  logging is DEBUG, every query included.

## CI

`test.yml` on every PR and push to `main`: uv with Python 3.13, `uv sync --group dev`, ruff check and
format check, ty, pytest — the tools directly, never through `just`, which the runner does not have.
It needs the network. `astral-sh/setup-uv` has published no floating major tag since v7, so it is
pinned to an exact release.

## Release

`just release` is the only way a version moves ([dogmas.md](dogmas.md#releases-and-deploys)); only
after CI is green on `origin/main`. **Publishing the GitHub release with its wheel attached is what
deploys**: a tag push alone creates no release. When a release fails after the push, re-run
`just github-release` alone. Its notes are generated by GitHub.

## Deploy

**Host: gravelines** — its address is not committed: `DEPLOY_HOST` in CI, the environment on the
laptop. The foundation — base packages, SSH, UFW, observability — is `server-setup`'s. The deploy is
`ansible/deploy.yml`, one playbook for both paths:

- **CI**: `deploy.yml` on a published release, or `workflow_dispatch` with a tag to redeploy an older
  one. It downloads that release's wheel — never a build of its own — and converges it, in a
  `concurrency` group so two converges never run at once.
- **Laptop**: `DEPLOY_HOST=<host> just deploy [tag]` — the latest release, or the one named. It is
  outside the workflow's concurrency group: converging while CI does restarts the bot twice.

Ansible refuses a shell whose stdio is non-blocking — an agent's shell, or `!` in Claude Code — with
"Ansible requires blocking IO". Give it a pseudo-terminal: `script -q /dev/null just deploy`.

The play uses only `ansible.builtin` (the `deploy` dependency group, out of `dev` so CI's test job
never installs it) and connects as `deploy` (`DEPLOY_USER` overrides), which needs passwordless sudo.
What a converge leaves on the host:

- `uv` at `/usr/local/bin/uv`, installed only if missing — other services share it — and **Python 3.13
  fetched by uv** into `/opt/uv/python`; the host's own is 3.11 (Debian 12).
- system user `krcg-bot`; venv `/opt/krcg-bot/venv`, the wheel installed with `--reinstall` — uv skips
  a same-version wheel and still exits 0, which would report a deploy of code that never landed.
- the token in `/etc/krcg-bot/env` (`root:krcg-bot`, 0640), read by `EnvironmentFile=`: an inline
  `Environment=` is readable by anyone who can run `systemctl cat`. Neither it nor the unit is written
  with a backup, so a rotation leaves no old token behind.
- unit `/etc/systemd/system/krcg-bot.service`: `Restart=always`, `RestartSec=5`,
  `PYTHONOPTIMIZE=1`, `TMPDIR=/opt/krcg-bot/cache` (the corpus-cache UID trap,
  [corpus.md](corpus.md#loading)) and **`RuntimeMaxSec=1d`** — the daily restart is the corpus
  refresh. Dropping either of the last two is a silent regression: a stale corpus, or a DEBUG journal.
  `journalctl -u krcg-bot.service`; `server-setup`'s Alloy ships the journal to Grafana Cloud Loki.

A restart drops the buttons' watchers and re-fetches the corpus, so a converge restarts only when the
wheel, the token or the unit changed. It then checks, 20 seconds on, that the unit is `active` **in
the same run** — `Restart=always` makes a crash loop pass through `active`.

### Secrets

`ansible/vault.yml` holds `discord_token`, committed ansible-vault-encrypted: the repo is public, so
it publishes the ciphertext of a live token, accepted (2026-07-26). ansible-vault's PBKDF2 is weak
against an offline attack, so the vault password is long and random. `-e discord_token=…` overrides
the vault if that ever stops being acceptable.

The vault password is committed age-encrypted as `ansible/secrets/vault-pass.age`, beside the dev
token's `dev-env.age`; both are readable by the public keys in `ansible/secrets/age-recipients.txt` —
one list, so the two cannot drift. `ansible.cfg` reads the git-ignored `ansible/.vault_pass`, which
must exist before even `--syntax-check`:

```shell
age -d -i ~/.ssh/<key> -o ansible/.vault_pass ansible/secrets/vault-pass.age
```

Adding a recipient: decrypt, append the public key, then
`age -R ansible/secrets/age-recipients.txt -o ansible/secrets/vault-pass.age < ansible/.vault_pass`
(and the same for `dev-env.age`). Removing one only stops future decrypts; revoking for cause means a
new vault password, `vault.yml` re-encrypted with it, and the CI secret updated.

CI reads the `production` environment, and **mixing up the two kinds fails silently**:
`DEPLOY_SSH_KEY` and `ANSIBLE_VAULT_PASSWORD` are secrets; `DEPLOY_HOST` and `DEPLOY_HOST_KEY` are
variables (`vars.`, not masked in logs). `server-setup`'s `just sync` sets all but the vault password.
