## Problem

`_build_components` builds its first row as `Make public` + `< Back` + one
button per variant, with **no cap**. Discord allows 5 buttons per row, so a
card with 4 variants emits 6 and the interaction fails with HTTP 400. hikari
2.5.0 validates only type homogeneity, so the payload reaches Discord. Button
labels are uncapped against the 80-character limit as well.

The corpus peaks at 2 variants, so the bot is two variants from breaking and
upstream controls that number.

The PLAN.md Queue entry that prompted this was **wrong** about the mechanism.
It claimed `_build_components` can emit more than 5 rows because `len(ret) >= 5`
breaks only the inner loop while a trailing append runs unconditionally. It
cannot: when `ret` reaches 5 the flush has just reset `row` to empty, so the
trailing `if len(row.components)` is false. Verified by reading
`src/krcg_bot/__init__.py:506-522` and by eng's exhaustive simulation over
variants × ruling-cards — max 5 rows, never 6. The rulings loop is correct; the
first row is not.

## Outcome

No card can produce an invalid component payload, and any button that has to be
dropped is logged rather than vanishing silently.

## Advisor input

eng:
- The reachable overflow is the first row, not the row count.
- Dropping is a correctness decision, not formatting. `< Back` is the only
  route into the `HISTORY` stack, so dropping it strands the user with no other
  UI. Variants and ruling links stay reachable through autocomplete, so they
  are the ones that can give.
- Silence is the real defect: a dropped button today leaves no trace anywhere.
- Worst path is `make_public`: `create_initial_response` blanks the ephemeral,
  then `asyncio.gather` deletes it *concurrently* with `execute_webhook`. A 400
  on the webhook means the ephemeral is already gone and the user loses the
  card outright. That handler has no test coverage.

## Grilling record

Lionel, live, one round:
- **Spill variants, never drop `< Back`.** Row 1 keeps `Make public` and
  `< Back`; variants move to their own row(s); ruling links are dropped last;
  every drop is logged.
- **No synthetic cards in tests.** T-003's rejection is honoured literally: a
  4-variant card does not exist in the corpus and will not be constructed to
  test against. Consequence accepted — the new capping code ships untested, as
  the existing limit assertions already are (`refs/eng`: they are inert
  because the corpus peaks at 4 rows, 2 variants, 35-char labels).

## Tasks

- Cap the first row at 5: keep `Make public` and `< Back`, spill variants into
  their own row(s).
- Drop ruling links last, and only once every row is full.
- Log a warning naming the card whenever a button is dropped.
- Truncate button labels to 79 characters plus an ellipsis, display-only —
  `custom_id` must not change, or `HISTORY` and the dispatch tables break.
- Verify: `just quality` and `just test` green. The new paths are not directly
  tested, per the decision above; state that plainly rather than implying
  coverage.
