## Problem

Three defects in the `HISTORY` navigation path, all live on today's corpus,
all in code with no test coverage.

1. **`< Back` disappears mid-stack.** A variant button is `switch-{id}` — one
   id — so `switch_card` leaves `origin_id` at `None` and renders no `< Back`,
   even when `HISTORY[message.id]` still holds frames. The
   `# no origin if we're not tracking history (eg. vampire variations)` branch
   was written for the top-level case and cannot tell "no history exists" from
   "history exists but this button did not carry it". Nine reachable paths in
   the corpus; the shortest is `/card Spell of Life` → ruling link
   `[Nefertiti (G2)]` → its variant button.
2. **The origin's ruling link vanishes.** `_build_components` does
   `links.add(int(origin_id))`, so once `< Back` is restored the origin card's
   own ruling-link button is suppressed on that page.
3. **The expiry never refreshes.** `card()` sleeps `COMPONENTS_TIMEOUT` from
   the original response, then strips components. The ephemeral `switch_card`
   path issues a `MESSAGE_UPDATE` and starts no timer of its own, so a reader
   who navigates for four minutes gets one minute of working buttons.

## Outcome

Navigation keeps its way back, keeps both routes to the origin card, and the
five minutes are five minutes of use rather than five minutes of wall clock.

## Advisor input

eng:
- Fix 1 by driving `< Back` from `HISTORY`, not from `custom_id`: `custom_id`
  drives the mutation, `HISTORY` drives the rendering. Carrying the origin in
  the variant `custom_id` instead would push a stack frame per variant toggle
  and needs two id formats anyway.
- `HISTORY` is a `defaultdict`: reading it inserts an empty list on every
  top-level variant click. Use `.get()`.
- The three risks raised against fix 1 are all safe: `< Back` arrives with
  `origin_id == 0`, never `None`; a popped-empty stack is falsy so no stale
  Back is resurrected; `make_public` pops before building and the public path
  already forces `None`.
