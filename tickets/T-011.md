## Problem

Two unguarded fragilities in the T-010 trail encoding, both raised by `eng` at review.

**(1) `MAX_FRAMES` holds only while every card id is 6 digits.** `_switch_id` zero-pads, so small ids are safe; the break is a 7-digit id, which spells a 7-char frame and desyncs `_parse_stack` into *wrong cards*, silently. `test_card_ids_are_fixed_width` catches it — but in CI, after a production bot has already emitted bad frames, and `test.yml` runs on `push`/`pull_request` only, with no schedule. A quiet month means the test never fires at all. That, not "fires late", is the argument for a load-time guard.

**(2) `switch` is shared by every encoding.** `_parse_stack` rejects the previous format by width and digits alone, so the next format that happens to be a multiple of 6 digits parses as plausible ids and answers with the wrong cards. Nothing distinguishes formats.

Trigger distance (live corpus, measured 2026-07-28): 4149 cards, library `100001–102365`, crypt `200001–201786`, nothing below `100000`. Seven digits is ~798k ids away. So (1) is remote and (2) is entirely under our own control — but a version char is nearly free *now* and stops being free once more formats have shipped. That is the shape of the decision.

## Outcome

No format change can silently answer with wrong cards, and a non-6-digit id is loud at startup, not only in CI.

## Advisor input

`eng`: conditional for, split.

- Build the version char. Reject the alternative of bumping the dispatch prefix: dispatch is `COMPONENTS[custom_id[:6]]`, so an unknown prefix is a `KeyError` → "Command error", not the `CommandFailed` a reader can act on. It also contradicts `.claude/rules/bot-code.md` §"Changing the `switch-` encoding without changing its 6-char dispatch prefix is what makes old buttons unreadable rather than merely wrong."
- The guard must be a real `if` in `load_cards()`. `PYTHONOPTIMIZE=1` in the systemd unit strips `assert`.
- The version char is itself a format change: it kills today's live buttons at deploy. Acceptable once, not twice — which is the point of doing it now.

## Grilling record

Lionel, 2026-07-28: build both — version char **and** startup guard. Section: **Now**.

`eng`'s open question "with one version, what tests the version char?" resolved during drafting: the *previous* format is a real second case, so the rejection path is testable today without inventing a v2.

## Tasks

1. `_switch_id` emits `switch-1` + frames. Derive `MAX_FRAMES` from the versioned prefix — `(100 - len("switch-1")) // 6` is still 15, full depth 98 chars.
2. `_parse_stack` rejects anything whose version char is not the current one, with the existing out-of-date `CommandFailed`. Keep the width and digit checks behind it.
3. `load_cards()` raises on any id outside `0 <= id < 10**ID_WIDTH` — a real `if`, not an `assert`.
4. Tests: `_parse_stack` rejects the legacy unversioned format; round-trip at full depth stays within `CUSTOM_ID_MAX`; the load guard raises on an out-of-range id.
5. `.claude/rules/bot-code.md`: the encoding line gains the version char and the load-time guard, and records that the 6-char `switch` dispatch prefix stays deliberately unchanged.
6. Deploying this breaks live buttons on open messages until their tokens die (≤15 min). That is the designed behaviour, not a regression — `_parse_stack` answers them with `CommandFailed`. Release is Lionel's call as always.
