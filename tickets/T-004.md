## Problem

`refs/shared/project.md` promises "anyone may self-host", and the README's
`pip install krcg-bot` is the how. Neither is true in practice: PyPI serves 79
downloads a month, 14 a week, 2 a day — mirror and scanner traffic, not people.
Lionel: "krcg-bot is not a publish package people self-host."

The distribution is also the last thing tying the project to PyPI. T-001 already
ships a locally-built wheel to the host, so the deploy no longer needs it; only
the legacy `myserver/krcg-bot.yml` still installs `krcg-bot` from PyPI, with
`state: latest`, onto the live unit.

## Outcome

One way to run the bot: Lionel's public instance, via the OAuth link. The PyPI
project is archived — no new uploads, existing installs untouched, the name
still held. `just release` stops publishing.

## Advisor input

pm:
- Do not free the name. `krcg-bot` consumes a `DISCORD_TOKEN`; a released PyPI
  name is a credential-harvest squat aimed at exactly the audience being
  dropped. Hold it.
- Dropping self-hosting makes the public instance the only bot: that uptime
  becomes Lionel's alone, and a fork is the only recourse for anyone who wanted
  their own.
- A release-asset wheel URL is worse self-host UX than `pip install`, and rots
  silently once nobody is watching it — an argument against the middle path.

eng:
- Archive, not yank, not delete: archiving blocks new uploads, keeps installs
  working, keeps the name, and is reversible. Yanking breaks the legacy deploy
  while it is still the live path.
- The stated replacement does not exist: `just github-release` is
  `gh release create --generate-notes` with zero assets. Moot now that
  self-hosting is dropped, but it means "replaced by GitHub wheels" was a plan,
  not a path.
- `deploy.yml` rebuilds its own wheel from the checkout, so a release asset
  would be a *different* artifact than the deployed one.
- `myserver/krcg-bot.yml` installs `state: latest` from PyPI onto the same unit
  and can overwrite T-001's deploy.

## Grilling record

Lionel, live, one round — all four settled, and this is the live sign-off that
files a strategic ticket as `todo`:
- **Self-hosting is dropped.** Public instance only. The Distribution fact and
  the README's "Hosting the bot" section go with it.
- **Archive, no final release.** No deprecation release first.
- **Now, in parallel** — not blocked on T-001's converge. Safe as chosen:
  archiving leaves existing installs working, so the legacy deploy keeps
  resolving 4.5 until it is retired.
- Section: **Now**.

Consequence drawn by the session, not a stated decision: retiring
`myserver/krcg-bot.yml` still waits for T-001's first successful converge,
because until then it is the rollback path.

## Open questions

- Who answers a self-hoster who asks? There is no supported answer after this —
  fork, or use the public instance. pm raised it; not settled.
- The README badge links `badge.fury.io/py/krcg-bot`. Archived projects still
  render a badge, so it would show a version nobody should install. Assumed
  removed with the rest.
