## Problem

`.claude/rules/bot-code.md` states the invariant "One module, no database, **no
state a restart cannot rebuild**." `HISTORY` is exactly that: a process-local
dict keyed by a Discord message id, with no owner and no lifecycle. A restart
strands every open message — buttons still there, stack gone.

Three defects shipped from this one function on 2026-07-26, and each was
reported with the **wrong mechanism** before eng corrected it:

- T-008 claimed `_build_components` could emit more than 5 action rows. It
  cannot; the real defect was an uncapped first row.
- T-009 fixed `< Back` vanishing on variant clicks — then the fix's own
  `finally` re-created the same stranding, because an expired interaction token
  is not a 404.
- The strip/click race was reported as a ~200ms PATCH window. It is not: a
  click Discord accepted before the strip can reach the gateway *after* the
  cleanup, and an HTTP response does not order gateway delivery.

Lionel, on being offered a fourth narrow patch: "Feels like you have a deeper
design issue if that's so hard to fix, no?" The three defects are symptoms of
server-side mutable state keyed by a client-owned id.

## Outcome

The navigation stack lives in `custom_id`. `HISTORY` is deleted. A button
encodes everything needed to answer it, so it survives a restart, and `< Back`
becomes "navigate to an ancestor with a truncated stack" — no `0` sentinel, no
pop branches, no defaultdict.

## Advisor input

eng, verified against current docs (`docs.discord.com/developers/components/reference`,
fetched 2026-07-26) — not recall:

- `custom_id` is **1–100 characters**; label max 80; "Up to 5 buttons" per row;
  "Messages allow up to 40 total components".
- Corpus measured: 4149 cards, **every id exactly 6 digits** (100001–201786).
  Fixed-width parsing needs no separator: `switch` + 6k ≤ 100 → **15 frames**.
  Dispatch already keys on `custom_id[:6]`, so the 6-char prefix is preserved.
- Truncating the oldest frame at the limit is correct: the chain shortens
  gracefully and never 400s.
- Subtraction, not a rewrite: ~60 lines out, ~15 in.
- **New failure introduced**: a retired card id on an old button reaches
  `CARDS[id]` and raises `KeyError` → "Command error". Must become
  `CommandFailed` with a readable message. More likely now that buttons can
  outlive a restart.
- Warned that keeping `_expire_components` leaves the leak and race "in
  miniature". Session's assessment, drawn from that and not contradicted by
  it: with `HISTORY` gone the survivors can only mean *one message's buttons
  are not stripped* and a small `EXPIRY` residue — the stranding class, the
  serious one, is dissolved by deleting `HISTORY` either way.
- `refs/eng/INDEX.md` lines 20–24 all become false and must be rewritten in the
  same change.
- `make_public`'s `HISTORY.pop(message.id, ...)` on the *public* message is
  already dead code — public messages never get entries. Delete it; do not
  "fix" it by adding tracking.

## Tasks

- Encode the stack in `custom_id`: `switch` + fixed-width 6-digit frames, the
  target last. Truncate the oldest frames past 100 characters.
- `< Back` targets the parent frame and carries the remaining ancestors. Delete
  the `switch-0-` sentinel form.
- Delete `HISTORY`, its defaultdict, every pop site, and the `origin_id`
  plumbing that existed to feed it. `_build_components` takes the stack.
- Keep `_expire_components` and `EXPIRY` (Lionel). Delete the dead
  `HISTORY.pop` on the public message in `make_public`.
- Wrap the retired-id lookup so an old button raises `CommandFailed`, not
  `KeyError`.
- Rewrite `refs/eng/INDEX.md` lines 20–24 and the `.claude/rules/bot-code.md`
  invariants they describe.
- Verify: `just quality` and `just test` green; a live-corpus sweep asserting
  no generated `custom_id` exceeds 100 characters at full depth. Then by hand
  on the test guild — three levels back, a variant click preserving back,
  `make_public`, and **clicking a button after restarting the bot mid-session**,
  which is the whole point and is only reachable manually.
