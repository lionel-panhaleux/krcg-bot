## Problem

`uv.lock` resolves `krcg` 4.18; latest is 5.9 (2026-07-20). krcg 5 is a rewrite,
not a bump.

hikari needs nothing: `uv.lock` already resolves 2.5.0, which is the current
PyPI latest. The requested "top hikari version" is a no-op beyond deciding
whether to pin.

## Outcome

The bot runs on krcg 5, pinned `>=5.9,<6`, with `just quality` green and
behaviour confirmed by hand against a test guild. No release.

## Advisor input

eng — what actually breaks:
- `krcg.vtes` / `krcg.cards` are deleted. The `VTES` singleton becomes
  `krcg.load()` → `CardDict`.
- Network loading is now `async load_online(aiohttp.ClientSession)`; plain
  `load()` reads a `/tmp` pickle cache. This breaks the documented invariant
  that a restart is the corpus-refresh path — unattended hosting must not serve
  a stale pickle.
- Renames hit nearly every embed field: `card_text`→`text`,
  `usual_name`→`unique_name`, `clans`→`clan`, `adv`→`advanced`, the three cost
  fields→`Cost`, `variants` dict→list. Rulings become typed `Ruling` objects,
  not dicts.
- `Card` splits into `CryptCard`/`LibraryCard`; strict mypy will reject today's
  single-typed `_build_embeds`.
- `card.id` survives, so button `custom_id`s and `HISTORY` hold.
- Cadence is hot: 5.0→5.9 in 22 days, 5.7 skipped.

## Grilling record

Lionel, live — approved porting to krcg 5 now, in these terms:
- Port now. The pin `>=5.9,<6` was proposed by the session and not explicitly
  confirmed; treat the ceiling as the recommendation, not a decision, and settle
  it when the work starts.
- Port lands **before** the test work ("port first, tests after"), so the suite
  is written once, directly against the krcg 5 API.
- **No release from this ticket.** Initially "port and release krcg-bot 5.0
  now", reversed in round 3: "hold the release until tests exist and green."
  Releasing is T-003's exit condition, not this ticket's.

## Open questions

- Does `static.krcg.org/data/v5/` stay published, and is the `/tmp` pickle cache
  acceptable for unattended hosting — or must the bot call `load_online` at
  startup to preserve restart-as-refresh?

## Tasks

- Replace `vtes.VTES.load()` with the krcg 5 loading path; settle the
  cache-vs-online question above first.
- Rewrite `_build_embeds` field access for the renames; split the crypt/library
  typing so strict mypy passes.
- Adapt rulings handling to typed `Ruling` objects.
- Pin `krcg>=5.9,<6`; decide a hikari floor or leave unpinned.
- Verify: `just quality` green, then `just serve` with the dev token against a
  test guild — `/card` on a crypt card, a library card, a card with rulings, and
  a multi-variant card, exercising every button.
